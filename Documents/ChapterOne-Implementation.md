**《最后一格电》完整第一关：开发评审结论与最终实施计划**

**一、开发结论：保留方向，收紧范围和规则**

上一份规划的玩家目标正确，但把干扰能力、正式 UI、音效、教程、统计、挑战和演出同时展开，容易把一个版本做成多个系统的半成品。本轮应收敛为：

**一个可靠的应急能力＋清楚的玩家界面与反馈＋简洁的关卡收尾。**

| 原规划的问题 | 开发判断 | 最终决定 |
| --- | --- | --- |
| 停机后再重置完整警觉 | 玩家已比敌人快；2.5 秒可移动约8.5米，再赠送1.2秒预警会过度削弱追击 | 保留停机，但不抹掉敌人已经确认的追击记忆 |
| 无需瞄准，但空放仍扣电 | 玩家难以准确判断4米范围，误操作惩罚大于决策价值 | 采用你选定的应急救援型：有效威胁才释放、扣费和进入冷却 |
| “电量必须大于12” | 12.001也可能通过，扣费及本帧消耗后立即耗尽；界面表达不明确 | 明确为**至少13电量才能使用，实际消耗12** |
| 直接往现有界面添加菜单 | 当前暂停状态下任意左键都会恢复，滑条、教程和结果按钮可能误触发游戏 | 先分离正式玩家 UI 与会话输入；F1 调试保留原方式 |
| 把“几分钟体验”作为目标 | 现有后台路线约15秒完成，不能据此推断人类体验时长，也不应靠等待凑时长 | 以独立理解目标、作出选择和完成一局为标准，时长仅供观察 |
| 挑战标签、历史成绩、复杂收尾一起做 | 增加统计定义、存储和演出状态，偏离本轮主线 | 延后；本版只做本局统计、结果页和短淡入收尾 |
| GitHub 项目整体引入 | 现有控制、AI和资源基础已经可用，整包迁移会引入额外依赖和回归 | 只借鉴局部设计，本版不增加第三方运行时框架 |

保留四区地图、一个敌人和现有宽松参数，不通过提高敌人速度或增加敌人来“补偿”干扰能力。

**二、锁定应急干扰的行为契约**

| 项目 | 最终规则 |
| --- | --- |
| 输入 | 新按下 Q 触发一次；按住不重复释放 |
| 可用状态 | 游戏正常运行，目标处于 **Alert 或 Chase** |
| 费用与门槛 | 当前电量至少13，成功释放扣12 |
| 有效范围 | 水平距离不超过4米，两者感知锚点之间无实体遮挡；无需朝准星瞄准 |
| 无有效目标 | 不释放、不扣电、不进入冷却，只给简短不可用提示 |
| 冷却 | 成功释放后15秒；暂停、失焦和结局期间不推进 |
| 命中效果 | 敌人进入 `Disrupted`，持续2.5秒；停止移动、转向、感知更新及捕获计时 |
| 与 E 的关系 | **成功释放**才取消当前交互，并要求先松开E；冷却中或电量不足的Q不会打断充电 |
| 恢复 | 恢复命中前的决策阶段，再依据真实可见性处理；不刷新隐藏玩家位置 |
| 重开 | 清空冷却、停机状态、捕获计时和本局使用次数 |

恢复规则具体为：

1. 命中前已在 Chase：恢复时仍看见玩家就继续 Chase，但捕获计时从零开始；看不见则搜索原有最后目击点。
2. 命中前仅在 Alert：保留此前警觉值，恢复后按原有“可见积累、遮挡消退”规则继续。
3. 不新增脉冲声源调查、通用听觉或攻击系统，也不让未确认的警觉跳过首次预警。

**同帧顺序必须固定：**

`运行状态检查 → E交互准备 → 玩家移动 → 解析Q并提交扣费/命中 → 敌人更新与捕获 → 门和资源推进 → 耗尽/逃脱判定`

这样有效 Q 可以阻止本帧尚未成立的捕获，但不能撤销上一帧已经确定的失败。扣费、停机、冷却和成功事件由一个控制点提交，音效和 UI 只接收结果，不参与重复扣费。

实现上新增 `EmergencyPulseController` 和敌人内部 `Disrupted` 状态。**不使用禁用 NavMeshAgent 或调用暂停开关来冒充停机**，避免把技能恢复与游戏暂停混在一起。

**三、本轮玩家体验的必做内容**

1. **轻引导与空间辨识。** 保留地图结构，在四区连接口增加名称、编号和局部色带。开局只有一张可跳过的简短说明；局内根据实际充电、供电和出口开放推进提示，首次警觉时提示 Q。重开不反复弹出教程，暂停菜单可重看操作说明。起步提示建议预留撤离电量，不把“达到36供电门槛”描述成“保证可以逃脱”。

2. **正式 HUD 与菜单。** 使用已安装的 uGUI＋TMP，玩家界面只保留电量、当前区域、目标、交互提示、警觉与 Q 冷却。F1 继续显示开发诊断。区分开局、运行、暂停／设置、结算界面；只有明确的开始或继续操作才能恢复游戏，点击滑条和按钮不会锁鼠标或误恢复。

3. **必要声光反馈。** 制作巡逻电机、警觉、追击、干扰命中与恢复、充电、供电／开门、胜败提示这一组核心反馈。敌人状态灯与实际状态同步，声音和文字／图标互相补充。取消交互、暂停和结局必须停止或暂停对应循环音效。灯光仅表达状态，不引入“暗处隐身”规则。

4. **可交付的资源与设置。** 本地目前缺少可打包的音频和中文字体，因此将素材制作计入任务。音效优先使用原创机械／电子音；中文采用 Noto Sans CJK SC Regular，并随包保留字体许可，不打包系统字体。该字体官方仓库提供简体中文 OTF，许可证为 SIL OFL 1.1。[字体来源](https://github.com/notofonts/noto-cjk/tree/main/Sans/OTF/SimplifiedChinese)、[许可文件](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE)。设置仅做主音量与鼠标灵敏度，保留当前灵敏度作为默认，并支持恢复默认。

5. **简洁结算。** 结局确定后冻结玩法，在可跳过的短淡入后显示结果、本局有效用时、剩余电量和成功干扰次数。有效用时不含开局说明、暂停和结算；无效 Q 不计次数。失败说明只使用能够证明的状态，例如“出口已供电，但撤离途中耗尽”。本版不做“反应慢”等推断，也不做历史排行榜、挑战解锁或复杂评分。

本轮延后配音、剧情对话树、动态音乐分层、相机接管过场、室外新场景和永久成长系统。

**四、工程组织与兼容边界**

1. **保留现有基线。** 新关卡体验使用独立场景副本与配置，新增内容集中放在 `Assets/ChapterOne`。原四区版、单房版和开发包保留；修改共享脚本前备份，新能力默认关闭，旧场景继续使用旧行为。

2. **Session 只协调玩法。** `ExpandedSession` 继续拥有模拟时钟、暂停和结局优先级；玩家 UI、声音及统计拆为独立组件。用少量明确的 C# 事件连接状态变化、交互完成、脉冲结果和结局，不建设通用事件总线框架。

3. **明确公开接口。** 干扰控制器提供释放结果、冷却状态和暂停／重置入口；敌人提供受约束的干扰入口；交互组件新增“取消并等待松键”方法，避免外部修改私有状态。新增只读 `RunSummary`，结局时生成一次，UI 不再自行计算或修改统计。

4. **输入与界面统一门控。** 暂停、设置、失焦和结局期间均不接受 Q；恢复后必须经过新的输入更新并确认 Q 已释放。沿用已验证的移动及 E 中性输入保护，不另写一套不一致的恢复规则。

5. **GitHub 只作局部参考。** 交互提示借鉴 [Studio-23 InteractionSystem](https://github.com/Studio-23-xyz/InteractionSystem)，视野反馈参考 [SebLague Field-of-View](https://github.com/SebLague/Field-of-View)，音频事件组织参考 [Open Project 1 的 AudioManager](https://github.com/UnityTechnologies/open-project-1/blob/main/UOP1_Project/Assets/Scripts/Audio/AudioManager.cs)。本版不整体导入这些项目，不替换已验收控制器，也不默认其代码许可覆盖音频或美术素材。

**五、实施批次、验收与交付**

| 批次 | 集中完成的工作 | 检查重点 |
| --- | --- | --- |
| 核心玩法 | Q 输入、扣费事务、停机恢复、E取消接口、配置 | 同帧Q与捕获、Q与E、13电门槛、遮挡、冷却、暂停和重开 |
| 玩家呈现 | 正式HUD、界面门控、轻引导、区牌、核心声光、设置 | UI操作不误恢复游戏；事件只触发一次；中文完整；暂停与循环音效一致 |
| 整合交付 | 本局统计、结算、完整路线与开发包 | 不使用Q仍能通关；使用Q后可继续完成；三种结局重开清理；最终一次整体试玩 |

后台检查必须覆盖这些新增组合风险：

1. 按住 Q 不重复扣费；无目标、冷却中、电量不足都不扣费。
2. 有效 Q 在捕获判定前生效，已成立的结局不能被技能撤销。
3. 干扰期间不感知、不移动、不捕获；恢复不会无故失忆，也不会追踪隐藏玩家的新位置。
4. 成功 Q 中断 E 后，仍按住 E 不会自动重新充电或供电。
5. 暂停冻结技能、AI和资源计时；界面操作不会意外恢复。
6. 重开后没有残留冷却、音效循环、订阅或重复统计。
7. 正式 HUD 在常见窗口尺寸下不遮挡关键目标，静音时仍能理解警觉、干扰和结局。

不再每个组件都要求用户进行桌面验收。实现期间只做后台合并检查和针对失败的复核；声画清晰度、音量和实际手感留到**同一个 Windows 试玩版本**集中体验。后台通过与用户试玩结论分开记录。

最终交付包含开发包、源码、配置、字体及音效来源说明、变更记录、汇总检查结果和哈希。本轮完成标准是：**玩家能独立理解关卡，干扰可靠且代价明确，反馈与规则一致，胜败后能清楚地结束或重新开始。**
