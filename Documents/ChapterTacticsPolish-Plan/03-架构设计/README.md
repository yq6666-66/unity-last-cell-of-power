# 03-架构设计

状态：整体方案参考；用户已澄清本次迭代不重复逐项确认，按active goal恢复实施。

数据流为：现有E或Q输入 → 原合法性与权威状态提交 → 只读反馈事件 → HUD、设备状态牌与诊断记录。新呈现组件不扣电、不推进AI、不改变门或声音持续时间。

| 模块 | 职责 |
| --- | --- |
| NoiseDevice | 保存本局已经实际响应过的机器人去重集合，只读提供ResponseCount；初始化清零 |
| TacticsDevices | 保持原规则；调查请求成功后记录响应；发布激活、响应、结束、门拒绝/取消/闭合等明确结果 |
| PolishFeedbackPresenter | 消费真实事件，管理一个短提示区域、优先级与有效游玩时钟，提供情境说明 |
| DeviceReadabilityView | 只读设备状态，更新编号相关状态文字和工作灯；禁用时恢复其拥有的呈现值 |
| TacticalReadabilityProfile | 集中目的地、文案、显示时长、配色等可选呈现配置 |
| ChapterPlayerUI | 保留双威胁和Q目标；可选接入新反馈与帮助卡，未配置时保持旧表现 |

诊断只记录设备编号、事件编号、帧号、实际结果和提示选择，不新增隐藏敌人坐标输出。提示选择日志不能冒充已经绘制的画面；状态与截图按各自帧关联。

新内容独立放Assets/ChapterTacticsPolish。对旧Runtime的最小增量限制在响应统计、反馈事件和可选UI连接；原资源、碰撞、导航、地图和AI参数用保护快照核对。
