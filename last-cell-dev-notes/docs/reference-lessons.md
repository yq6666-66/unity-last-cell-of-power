# 第二条链接：提取有用方法

参考：铁锤人（@lxfater）《手把手教你 VibeCoding 出人生中的第一个 3D 游戏》。[用户提供的原文](https://x.com/lxfater/status/2118173426980720665)，[本次用于读取的镜像](https://nitter.gq/lxfater/article/2118173426980720665)。

## 原文方法，简要转述

- 先说明游戏目标、操作与完成条件，再拆成带依赖和验收要求的任务。
- 先用简化场景跑通可玩流程，再投入精修。
- 区分模型形状与表面效果问题，复杂资产可以拆开改，不必每次全部重做。
- 用实际画面记录回看效果、收集反馈并迭代。

以上为转述，未复制文章截图、素材或代码。作者的开发速度和成本属于个人案例，不是本项目的工期或费用承诺。

## 应用到《最后一格电》的建议

以下是针对本项目提出的应用方案，不冒充作者原话：

| 方法 | 本项目怎么用 | 禁止扩张的范围 |
| --- | --- | --- |
| 规格先行 | 每张 Codex 任务单写清基线、允许文件、保护项、输入、预期结果与证据 | 不用“优化一下”代替验收要求 |
| 小样验证 | 先做出生点与门洞方向两个固定视角的明暗对比 | 不同时改地图、AI、充电和结局 |
| 分类诊断 | 先判断问题来自几何、材质、照明、相机还是 HUD | 不因画面暗就重做资产或迁移引擎 |
| 局部迭代 | 场景副本与单一写入者；审查、测试可并行 | 不让多个代理同时覆盖同一场景 |
| 真实反馈 | 同机同设置截图，附正常输入行走视频及测试标签 | 手机看视频不等于手机运行通过 |
